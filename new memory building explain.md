This is the core Python script that acts as the "brain" for building memories. It captures visual data (images) and audio data, generates text descriptions (captions) for both using AI models, synchronizes them based on time, and stores them in a database.

#### **Class: `AudioCaptioningModule` (The ACT Backend)**
This class handles the "ACT" model for audio captioning.
*   **`__init__`:** Sets up the microphone (PyAudio), finds the correct input device (e.g., "BlackHole" for routing system audio), and initializes the ACT AI model.
*   **`setup_act_model`:** Loads the configuration, vocabulary, and pre-trained weights for the ACT model. It creates dummy files if real ones are missing to prevent crashes during testing.
*   **`preprocess_audio_for_act`:** Converts raw audio waves into a "Mel-spectrogram" (a visual representation of sound) which is the format the AI model understands.
*   **`generate_audio_caption`:** Runs the AI model on the processed audio to generate a text sentence (e.g., "A dog barking").
*   **`capture_audio_chunk`:** continuously records audio into a buffer until it has a 10-second chunk ready for processing.

#### **Class: `AudioSetTaggingModule` (The AudioSet Backend)**
This class handles the "AudioSet" model, which is an alternative to ACT.
*   **Difference:** Instead of generating a sentence, this model usually outputs tags (e.g., "Music", "Speech", "Vehicle").
*   **`setup_audioset_model`:** Complex logic to find and load the specific CNN (Convolutional Neural Network) architecture (like `Cnn14`) used for tagging.
*   **`generate_audio_caption`:** Runs the model and returns the top 5 most likely sound tags with their confidence scores.

#### **Class: `FastVLMCaptioner`**
*   **Purpose:** A visual captioning backend using the **FastVLM** (LLaVA-based) model.
*   **Logic:** Loads a vision-language model optimized for speed. It takes an image path, processes the image, and asks the model to "Describe the image."

#### **Class: `GemmaMlxVlmCaptioner`**
*   **Purpose:** Another visual backend using Google's **Gemma** model via the Apple MLX framework (optimized for Mac Silicon).
*   **Logic:** Instead of loading the model into Python memory directly, it runs a subprocess command (`python -m mlx_vlm.generate`) to generate the caption. This isolates memory usage. It parses the text output to find the actual description.

#### **Class: `MultimodalMemoryItem`**
*   **Inheritance:** Extends the standard `MemoryItem`.
*   **Enhancement:** Adds a specific field `audio_caption` to the data structure, ensuring that when data is saved to the database, it includes both what was seen and what was heard.

#### **Class: `EnhancedMemoryBuilder` (The Main Controller)**
This is the orchestrator class that ties everything together.

1.  **`__init__`:**
    *   Connects to the Milvus database.
    *   Initializes the chosen Visual Backend (Phi-3, FastVLM, or Gemma).
    *   Initializes the chosen Audio Backend (ACT or AudioSet).
    *   Sets up queues (`visual_queue`, `audio_queue`, `memory_queue`) to pass data between threads.

2.  **`visual_processing_thread`:**
    *   **Loop:** Constantly watches a temporary folder (`/tmp/webots_memory`) for JSON files generated by the robot simulation.
    *   **Action:** When a file appears, it reads the image path, generates a caption using the visual model, calculates the timestamp, and puts the result into the `memory_queue`.

3.  **`audio_processing_thread`:**
    *   **Loop:** Constantly records 10-second chunks of audio.
    *   **Action:** Generates a caption/tag for the audio and puts the result into the `memory_queue`.

4.  **`memory_integration_thread`:**
    *   **The Challenge:** Visual data and Audio data arrive at different times.
    *   **The Solution:** It buffers (holds onto) visual items. When an audio item arrives, it looks through the visual buffer to find images that happened at roughly the same time (within a 15-second window).
    *   **Merging:** It combines the visual caption and the audio caption into a single `MultimodalMemoryItem` and inserts it into the Milvus database.

5.  **`run`:** Starts all the threads and keeps the program alive until the user hits Ctrl+C.

#### **`if __name__ == "__main__":`**
*   Parses command-line arguments (collection name, backends to use, etc.) and launches the `EnhancedMemoryBuilder`.
